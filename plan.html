Twelve months, four tasks, three milestones

The project starts with the specification, develops the adaptive control model alongside it, integrates a prototype, and then spends the second half benchmarking under representative agentic workloads. Early experimental feedback is used to refine both the protocol and the control mechanism.

start: February 2027 duration: 12 months milestones at M4, M9, M12

figure 4 · implementation plan

Tasks overlap deliberately: the controller is developed while the protocol is still being specified, and benchmarking begins before the prototype is integrated, so that problems surface while there is still time to act on them.

How it will be evaluated

Evaluation exposes the protocol to representative agentic AI workloads with varying message sizes, priorities, dependencies, arrival rates, subscriber behaviour, and network and resource conditions.

Particular attention goes to two things: the conditions under which adaptation provides measurable benefit, and the cases where conventional deterministic handling remains preferable. A result that maps the second set honestly is as useful as one that expands the first.

Experiments will use departmental computing infrastructure and NAISS resources including GPU-enabled systems, complemented by GPU infrastructure at TU Wien for large-scale distributed training and inference.

What gets measured

Communication performance
Latency and throughput, deadline satisfaction, delivery reliability.
Queue behaviour
Queue occupancy, and the volume of stale and redundant traffic that never needed to be sent.
Resource consumption
Bandwidth and memory used by communication.
Cost of the controller
Adaptation time and the processing overhead the control loop introduces — the number that decides whether any of the rest was worth it.

What CrowMQ could establish

Beyond the prototype, the project aims to produce reusable protocol abstractions and design principles for bounded communication intelligence: messaging systems that observe runtime conditions, make controlled adaptive decisions under uncertainty, and provide traceable communication behaviour.

Its context-aware mechanisms could reduce redundant traffic, improve message timeliness and use network, buffer and computing resources more efficiently across heterogeneous edge–cloud environments.

Results and access

Results will be managed according to the host university's intellectual-property policies and the terms of the funding agreement. Each result will be assessed for the most appropriate exploitation pathway — intellectual-property protection, open-source release, or protocol standardisation — balancing scientific dissemination against industrial adoption and interoperability.
