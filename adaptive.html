Deciding well when you can only see part of the picture

A broker never observes the communication state directly. It sees queue lengths, delays and acknowledgements, and has to act on what those imply. Active Inference is a framework for exactly that: sequential decision making when the state is only partially observable.

figure 3 · the observe, infer, evaluate, act loop

Once a policy is applied, the resulting queue state, delivery behaviour, acknowledgements and resource usage become new observations, which closes the loop.

The generative model

CrowMQ maintains a lightweight generative model relating observable communication measurements to a small set of hidden system states, the available message-management actions, and the preferred operating conditions.

As new observations arrive, the controller updates its beliefs about those conditions rather than relying exclusively on historical averages or fixed thresholds. That is the difference between reacting to a queue that has already grown and acting on the likelihood that it will.

What the hidden states represent

Conditions that matter for message handling but cannot be measured directly:

  • the likelihood of sustained congestion, as opposed to a passing spike;
  • delivery risk for messages currently in flight;
  • subscriber readiness, including whether an unavailable subscriber is likely to return;
  • the probability that queued information will lose its usefulness before it is delivered.

Choosing a policy

At each control interval the controller considers only the actions the protocol permits, and estimates how their consequences are likely to affect future communication conditions. Expected Free Energy provides the selection criterion, so both the expected value of reaching preferred conditions and the uncertainty about future outcomes are weighed.

An urgent message with a deadline at risk

Promoted ahead of other traffic, because the cost of missing the deadline outweighs the delay imposed on everything behind it.

Low-priority traffic under bandwidth pressure

Aggregated, accepting extra waiting time in exchange for lower per-message overhead while the constraint lasts.

A superseded message whose replacement has arrived

Removed, because delivering both wastes bandwidth and risks a subscriber acting on state that is already known to be stale.

A subscriber expected to recover shortly

Its traffic is buffered rather than failed, on the belief that availability will return before the memory cost becomes the larger problem.

The target is an equilibrium, not a maximum

Preferred operating conditions are defined around a balance between three interdependent dimensions, expressed as configurable preferences so that different applications can favour different operating regions without changing the protocol.

quality

Communication quality

Latency, freshness, deadline satisfaction, throughput and delivery reliability.

resources

Resource utilisation

Bandwidth, buffer capacity, memory and the processing consumed by communication itself.

cost

Operational cost

The consequence of using those resources: communication, computation and energy expenditure.

They pull against each other

  • Immediate transmission reduces latency but increases network and processing demand.
  • Aggressive buffering tolerates temporary subscriber unavailability but increases memory pressure.
  • Batching reduces communication overhead but increases waiting time.

So the objective is stated differently

Not to identify one universally optimal message policy, but to maintain an appropriate communication equilibrium as workload and infrastructure conditions evolve. A single-metric optimisation would simply move the problem to whichever dimension was left out.

The Markov blanket

The blanket provides a formal boundary for the decision process rather than an additional optimisation mechanism. It says precisely what the controller can see and what it can change.

This is also what prevents the communication intelligence from becoming an unbounded autonomous agent. CrowMQ infers the state of the communication process and acts on that process; the goals and reasoning of the communicating agents remain external to it.

Keeping the controller honest

Bounded by the protocol

Only actions in the permitted space, and only when delivery, security and resource constraints are satisfied.

Deterministic fallback

Insufficient evidence, high uncertainty or an exhausted processing budget all mean the broker continues with a valid fixed policy.

Measured overhead

Decision latency, adaptation time and control overhead are indicators for goal G2, not footnotes.
